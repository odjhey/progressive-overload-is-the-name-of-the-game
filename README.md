# Progressive Overload

A local-first workout log used by friends, built as an offline PWA.
See [progressive overload](https://en.wikipedia.org/wiki/Progressive_overload).
Live app: https://gains.odjhey.com.

## Development

Use Node 24 (`.nvmrc`) and Yarn Classic 1.22.22. The supported Node range is
22.13+ on the 22.x line, or 24+. Keep `yarn.lock` as the dependency lockfile.

```sh
yarn install --frozen-lockfile
yarn dev
yarn lint
yarn build
yarn preview
```

If Yarn is unavailable, use `npx --yes yarn@1.22.22` in place of `yarn`.
Installation configures Husky; the pre-push hook runs lint and build.
The service worker is generated by the production build, not the dev server.
Use `yarn preview` on localhost to exercise offline behavior.

### Local-trunk revival workflow

Use `next` in the main checkout as local trunk. Make code changes and commits in
task worktrees under `.worktrees/`, run the affected checks and application smoke
there, then integrate verified commits into local `next`. Do not push or deploy
as part of local integration.

PR intent reviews belong in comments on the existing PRs: preserve the original
request, restate the observable outcome and acceptance criteria, and distinguish
implementation gaps from product decisions. Review comments do not close PRs or
authorize their proposed implementation.

## Existing users' data is the compatibility contract

Never merge a change that invalidates existing local data. Schema changes need
a migration approach that preserves existing records.

The app uses localforage's default database and these keys:

| Key                   | Stored value                   |
| --------------------- | ------------------------------ |
| `ZLDKSJF`             | `{ lifts: [...] }`             |
| `TAGSlksajdf`         | `{ tags: [...] }`              |
| `PersistendFilterakj` | `{ tags: [...], term: "..." }` |

Lift identity is the exact name/date pair. Tags reference the lift name.
Do not change keys, envelopes, date conventions, or identity as incidental cleanup.
Keep the production origin unchanged: browser storage does not follow a new
hostname, scheme, or port.

Before an upgrade, use About → Raw Data to download each key's JSON. CSV is
not a full backup: it omits units, notes, tags, and filters. Raw upload overwrites
the supplied key; it does not merge or validate the contents. Restore only a
trusted backup to its matching key.

For upgrade smoke checks, use a disposable browser profile: load the previous
production build, create a workout and tag, then serve the new build at the same
origin without clearing storage. Verify worker takeover and unchanged stored
values before mutations, then create/edit/copy, toggle history/filter by tag,
export and restore raw JSON, and reload/save offline. Deploy all generated
assets, including `sw.js` and the Workbox runtime. The existing auto-update
policy reloads the app when an updated worker takes over.

## Housekeeping refresh

The refresh updates Vite/PWA/Workbox, TypeScript, ESLint's flat configuration,
Prettier, and Husky; refreshes compatible runtime dependencies and transitives;
and repairs the baseline lint failures. It retains React 18, Router 6, DaisyUI 3,
Tailwind 3, and localforage 1.10.0. Vite's production compilation targets retain
the previous Chrome 87 / Edge 88 / Firefox 78 / Safari 14 floor; this is not a
claim of device-level testing.

The refreshed lockfile's audit reports zero high/critical entries and five
moderate dependency-path entries across three advisories:

- [Router open redirect](https://github.com/advisories/GHSA-wrjc-x8rr-h8h6):
  current navigation uses fixed internal pathnames.
- [Router SSR hydration](https://github.com/advisories/GHSA-337j-9hxr-rhxg):
  this app does not perform SSR/hydration.
- [Selector parser CPU exhaustion](https://github.com/advisories/GHSA-rj75-hqrm-r3gf),
  reported through three Tailwind/DaisyUI dependency paths: CSS processing uses
  trusted repository sources at build time, not user-supplied selectors.

These are retained findings, not a zero-vulnerability guarantee. Reassess them
if navigation, SSR, or CSS input handling changes. Do not force incompatible
transitive versions solely to make the audit green.
